# OpenList Strm

直接读取 OpenList 目录树生成 strm 文件，**无需把 OpenList 挂载到本地**。

## 核心策略：视频生成 strm，字幕等下载为本地文件

这两类文件必须区别对待，否则媒体库会出问题：

| 文件类型 | 处理方式 | 原因 |
| --- | --- | --- |
| **视频**（`.mkv` `.mp4` 等） | **生成 `.strm`** | 体积大，用 strm 指向云盘直链即可播放，不占本地空间 |
| **字幕**（`.srt` `.ass` `.sup` 等） | **下载为本地真实文件** | Emby/Jellyfin/Plex 播放时读同目录字幕；strm 无法承载字幕 |
| **元数据**（`.nfo` `.xml`） | **默认跳过** | MoviePilot 刮削流程会自己生成，插件再下载一份会重复且互相覆盖（实测曾产生 4949 个重复 `.nfo`） |
| **图片**（`.jpg` `.png` `.webp`） | **默认跳过** | 同上，刮削器会自行获取封面 |
| **其它**（`.txt` `.html` `.url` 等） | **忽略** | 通常是说明或广告，无媒体库价值 |

字幕是 KB 级小文件，下载成本可忽略。**两类扩展名与跳过规则都可自定义**；
若确实需要远端自带的 NFO/封面，把它们加进「下载扩展名」即可恢复旧行为。

### 内置的无关文件过滤

不需要手工配置，插件已内置跳过：

- **20 类垃圾目录**：`@eaDir`、`#recycle`、`$RECYCLE.BIN`、`lost+found`、`.git`、`.stfolder`、
  `node_modules`、`System Volume Information` 等；**所有以 `.` 开头的隐藏目录也一律跳过**
- **32 类无关文件**：`Thumbs.db`、`desktop.ini`、`.DS_Store`、各类下载临时文件
  （`.tmp` `.part` `.crdownload` `.!qb` `.aria2`）、`*.url`、`*.lnk`、`*.db`、`*.ini`、
  `*.log`，以及含「广告、推广、最新地址、获取方式、更多资源、请勿、必看、公告」的文件

还可按需追加自己的跳过规则（目录名精确匹配；文件名支持 `*` `?` 通配）。

## 为什么需要它

MoviePilot 常见的「云盘 → strm」做法是先把云盘通过 CloudDrive2 / WebDAV / rclone
挂载成本地盘，再用 CloudStrm 之类的插件扫描本地目录。这套方案有两个痛点：

1. **必须挂载**：要在 NAS 上额外运行一个挂载进程，占用资源且容易掉线；
2. **路径映射复杂**：插件要同时理解「本地挂载路径」「媒体服务器内路径」「云盘路径」三套
   路径，配置错一个字符就整条规则失效。

本插件绕开挂载：直接调用 **OpenList HTTP API** 递归遍历目录树，视频写成 `.strm`
指向 `/d/` 直链，附属文件直接下载。于是：

- 不需要任何挂载进程；
- 只需要两个路径：**OpenList 里的路径** + **本地输出目录**；
- 生成的链接由 OpenList 在播放时实时解析，不依赖挂载状态。

## 工作原理

```
OpenList 实例 (HTTP API)
        │
        ├─ ① 索引优先：POST /api/fs/search（scope=1 拿目录）
        │      索引可用时一次查询拿到整棵子树，O(1) 请求
        │      ▼ 索引未启用/未建完/超时
        └─ ② 自动回退：POST /api/fs/list 并发分层 BFS（默认 8 线程）
               ▼
   目录树缓存（按 mtime 复用，可选）
        │
        ├─ 垃圾目录/无关文件 ──▶ 直接跳过（内置 + 自定义过滤）
        ├─ 视频扩展名 ────────▶ 写入 .strm（内容 = /d/ 直链）
        └─ 下载扩展名 ────────▶ GET /d/<path> ──▶ 原子写入本地真实文件
        ▼
MoviePilot 目录监控 → 刮削 → Emby/Jellyfin 播放
```

**两条路径产出完全一致**（有 9 个回归测试锁定这一点），索引只是加速手段。

接口契约来自 OpenList 官方源码（`OpenListTeam/OpenList`）：

| 用途 | 端点 | 依据 |
| --- | --- | --- |
| 登录 | `POST /api/auth/login` | `server/router.go` |
| 列目录 | `POST /api/fs/list` | `server/handles/fsread.go` |
| **搜索索引** | `POST /api/fs/search` | `server/handles/search.go`，走 `search_index` 后端 |
| 账号信息 | `GET /api/me` | 取 `base_path` |
| 直链（strm 内容 + 下载） | `GET /d/*path` | `server/router.go`，播放时实时解析 |

几个关键实现细节：

- **`Authorization` 头放 token 原文，不加 `Bearer `**。OpenList 直接 `ParseToken()`
  解析该值，加了前缀会导致 JWT 校验失败。
- **`per_page=0` 表示「返回全部」**。源码 `internal/model/req.go` 的
  `PageReq.Validate()` 把 `<1` 转成 `MaxInt`，一次请求即可拿完整个目录。
- **API 错误也是 HTTP 200**，必须判断响应体里的 `code`。
- **路径不存在的返回是 `code=500` + `object not found`**（不是 404）。
- **`/d/` 直链路径要逐段做 URL 编码**，与 OpenList 自身的 `utils.EncodePath(path, true)` 一致。
- **`/api/fs/search` 的 `parent` 是「递归匹配整棵子树」**，不是只匹配直接子级；
  每个命中项自带完整 `parent` 路径，因此一次查询就能重建整棵树。
- **`scope`**：`0`=全部、`1`=仅目录、`2`=仅文件。先查 `scope=1` 拿目录骨架，
  再按目录查 `scope=2` 拿文件，避免一次性拉全量文件导致服务端 `Count` 超时。

### 为什么需要双模式

OpenList 的索引后端（Meilisearch / Bleve / 数据库）在建索引期间、或未启用时，
`/api/fs/search` 会返回空或超时（实测大库 `scope=2` 会 HTTP 554 超时）。
**只依赖索引会让插件在索引未就绪时完全不可用**，因此索引只作为加速层，
失败即无痛回退并发遍历。

## 性能

### 并发遍历（v1.6.0）

逐目录请求本身有固定延迟（实测单次 `/api/fs/list` 约 111ms，`/EmbyCloud` 有 857 个目录，
串行需约 95s）。插件改为**分层 BFS + 线程池**，同一层的目录并行请求：

| 线程数 | 耗时 | 相对串行 |
| --- | --- | --- |
| 1（串行） | ~95s | 1.0× |
| **8（默认）** | **~16s** | **5.9×** |
| 16 | ~17s | 5.7× |

> 8 线程已接近收益上限（16 线程无进一步提升，反而因服务端磁盘竞争略慢）。
> 配置项「并发线程数」可调，范围 1–32。

### 搜索索引（需 OpenList 侧启用）

OpenList 启用 Meilisearch 索引后，整棵子树一次查询即可返回：

| 查询 | 无索引 | 有索引 |
| --- | --- | --- |
| 857 个目录（`scope=1`） | ~95s（需 857 次请求） | **~165ms** |
| 小库文件（`scope=2`） | ~11s | **~244ms** |

> 大库的 `scope=2` 在索引**建完之前**仍会偏慢，插件会自动回退到并发遍历，
> 不会因此失败。索引建完后建议重新扫描一次以享受加速。

## 三大进阶能力

### 1. 目录树持久化缓存（解决大库扫描慢）

OpenList 没有「一次拉取整棵树」的 API，只能逐目录请求。规模大的库（实测
795 个目录 / 1.4 万文件）首次全量扫描需要约 2 分钟。

插件会把「目录 → 条目」按目录持久化到磁盘，并记录目录 mtime：

- **mtime 未变** → 直接复用缓存，**不再发请求**；
- **mtime 变化** → 重新拉取该目录并更新缓存；
- **远端目录已删除** → 扫描结束后自动淘汰其缓存。

**实测效果**（真实实例，795 个目录 / 14691 个视频）：

| | 冷缓存（首次） | 热缓存（第二次） |
| --- | --- | --- |
| 耗时 | **114.0s** | **0.3s**（约 361×） |
| 请求数 | 795 | **1**（减少 99.9%） |
| 结果 | 14691 个 strm | 14691 个（一致） |

> **注意**：扫描根目录每次都会重新拉取（它没有父条目提供 mtime），这样才能感知
> 顶层新增/删除的文件；其余子目录按 mtime 命中缓存。每规则只多一次请求。

配置项「缓存最长有效时长」默认为 `0`（完全依赖 mtime）。若某些存储驱动不维护
目录 mtime，可设为 `24` 强制每天刷新一次。

### 2. 多任务：分开定时、错峰执行

一个任务 = 一套扫描规则 + 一个执行周期 + **一份独立的 OpenList 连接信息**。
把大库拆成多个任务各自调度，单次任务更短、更可控。

**配置格式（一行一个任务，直接在文本框里写）**：

```
任务名 | OpenList地址 | Token或账号:密码 | 扫描规则 | 执行周期 | 选项
```

- 只有**前 4 段必填**，后两段可省略
- 以 `#` 开头的整行视为注释，空行会被忽略
- 扫描规则里可能含 `#`（规则自身分隔符），所以字段用 `|` 分隔；
  一个任务有多条规则时用 `;` 分隔

示例：

```
# 电影库
电影 | https://openlist.example.com | openlist-xxxxxxxx | /EmbyCloud/电影#/volume1/video/strm/source | 0 30 4 * * *

# 动漫库：用另一个 OpenList 实例，顺带检测失效
动漫 | https://ani.example.com | admin:我的密码 | /Ani#/volume1/video/anistrm/source | 0 30 6 * * * | detect

# 剧集库：不写周期则默认每天 04:30
剧集 | https://openlist.example.com | openlist-yyyyyyyy | /EmbyCloud/电视剧#/volume1/video/strm/source
```

**凭据字段**支持两种写法：

| 写法 | 说明 |
| --- | --- |
| `openlist-xxxxxxxx` | 后台「设置 → 其他」复制的 Token（推荐）。以此为前缀的字段一律按 Token 处理 |
| `用户名:密码` | 插件自动登录换取 JWT（默认 48 小时，失效自动重登） |

> **字段切分说明**：插件以「第一个 `http(s)://` 字段」为锚点定位地址，并从行尾倒推
> 周期与选项。因此：
> - 任务名里可以含 `|`（如 `电影|剧集`），不会被截断
> - **扫描规则里的正则交替可以正常写**（如 `\.(mkv|mp4)$`），正则不会丢失
> - 周期与选项可省略、也可只写其一

**选项字段**（逗号分隔，可省略）：

| 选项 | 含义 |
| --- | --- |
| `force` | 强制覆盖已存在的 strm |
| `detect` | 本任务完成后检测失效 strm（**只检测，不删除**） |
| `off` | 停用该任务 |

**执行周期写法**：6 段（`0 30 4 * * *`）与标准 5 段（`30 4 * * *`）**都支持**，
6 段会自动忽略秒字段。留空则默认每天 04:30。

> **多 OpenList 实例**：每个任务自带地址与凭据，因此可以同时对接多个不同的 OpenList
> 服务，互不影响。日志与页面都会显示脱敏后的凭据（如 `Token openlist-3dd…cY4n`）。

### 3. 失效 strm 检测与联动清理（安全模式）

当 OpenList 上的文件被删除或移动后，本地 strm 会变成死链。插件可以找出来并清理。

> ⚠️ **重要：保存配置与定时任务都不会删除任何文件。**
> 流程固定为「**先检测 → 看到清单 → 手动确认清理**」三步。

**操作步骤**：

1. 在配置页点 **「① 检测失效 strm」**
2. 打开插件**详情页**，在「失效 strm」卡片中查看清单
   （每行显示远端路径、失效原因，以及可联动的硬链接数、转移记录数；
   清单超过 50 条时表头会明确提示「清理时会处理全部 N 个」）
3. 确认无误后，在详情页点 **「② 清理失效项」**（未检测时该按钮为禁用状态）

**检测方式**（先粗筛再精查，兼顾速度与准确）：

1. **粗筛**：复用扫描得到的「远端现存文件集合」，与本地 strm 反解出的路径求差集；
2. **精查**：对差集中的路径调用 `/api/fs/get` 逐个确认，避免遍历遗漏导致误判。

**联动清理**（三项独立开关，默认只删 strm 本体）：

| 对象 | 默认 | 说明 |
| --- | --- | --- |
| **删除失效 strm** | 开 | 删除死链的 `.strm` 本体 |
| **同时删除硬链接** | 关 | MoviePilot 以 `mode=link` 整理 strm 时，会在媒体库目录生成同一个 strm 的**硬链接**；删掉它只减少引用计数，不影响下载目录里的源文件 |
| **同时删除转移记录** | 关 | 删除 `transferhistory` 中对应记录，避免残留「已整理但文件已失效」的脏数据 |

> ⚠️ **安全设计**（已由测试覆盖）：
> - **远端文件永不被删除**，插件只读 OpenList；
> - **只清理你在清单里确认过的那批**：删除时以详情页展示的清单为准，不会
>   「重新检测后全删」——因此检测之后新产生的失效项不会被顺手删掉；
> - 删除前对每一项**再复核一次远端状态**，若文件已恢复则跳过不删；
> - 只处理内容能被反解为 `/d/<path>` 的 strm —— **其它来源的 strm 一律跳过**，
>   不会误删你手写的或别的插件生成的 strm；
> - **跨实例防护**：多任务共用同一输出目录时，只处理 host 与当前实例一致的 strm，
>   并在删除前二次校验，避免用 A 实例的凭据判断 B 实例的文件；
> - 所有删除路径必须位于规则声明的输出目录内，越界一律**拒绝**；
> - 删除硬链接前用 `samefile()` 校验 inode 一致，确保是同一份数据。

**清空全部 strm**（危险操作）同样采用两步确认：详情页点「① 预览将被清空的 strm」
查看清单，确认后再点「② 清空全部 strm」。

## 安装

### 1. 添加到插件市场

在 MoviePilot「设置 → 插件 → 插件市场」中添加本仓库地址：

```
https://github.com/G1deonChan/MoviePilot-Plugins
```

然后搜索 **OpenList Strm** 安装。

> 本插件使用 V3 目录与索引（`plugins.v3/` + `package.v3.json`），需要
> **MoviePilot v3.0.0 及以上**。

### 2. 准备 OpenList 凭据

推荐在 OpenList 后台 **设置 → 其他** 复制 **Token**（形如 `openlist-xxxx-...`），
插件用它认证最简单，且不受密码修改影响。

也可以填 OpenList 的**用户名 + 密码**，插件会自动换取 JWT（默认有效期 48 小时，
Token 失效时插件会自动重新登录一次）。

> 若账号开启 2FA，请在「两步验证码」中填写当前验证码。一次性验证码会过期，
> 长期运行建议改用后台 Token 或关闭该账号的 2FA。

### 扫描规则格式

```
OpenList路径#本地输出目录[#包含正则[#排除正则]]
```

- 以 `#` 开头的整行视为注释，空行忽略
- 也支持用 `|` 分隔（取出现次数更多的那个分隔符，避免与正则冲突）
- 一个任务有多条规则时，在任务行里用 `;` 分隔
- **包含正则只作用于文件**，不会因为父目录不匹配而剪掉整棵子树
- **排除正则同时作用于目录和文件**，可用于提前剪枝、减少请求

示例：

```
# 电影库
/EmbyCloud/电影#/volume1/video/strm/source

# 动漫库：跳过所有预告片目录
/Ani#/volume1/video/anistrm/source##/[Ss]ample|预告
```

### 与 MoviePilot 目录监控配合

在 **设置 → 目录**中确认有一条 `monitor_type = monitor` 的目录，其**下载目录**指向
插件输出目录，**媒体库目录**指向刮削后的目标：

| 名称 | 下载目录（插件输出） | 媒体库目录 |
| --- | --- | --- |
| strm | `/volume1/video/strm/source/` | `/volume1/video/strm/target/` |

插件负责写 strm 和下载字幕；识别、重命名、刮削、通知由 MoviePilot 目录监控完成。

## 生成的 strm 长什么样

以 `/Ani/2019-1/輝夜姬想讓人告白～.../[ANi]...～[01][1080P].mp4` 为例：

**生成的文件**（扩展名被**替换**为 `.strm`，不是追加）：

```
<本地输出目录>/2019-1/輝夜姬想讓人告白～.../[ANi]...～[01][1080P].strm
```

**文件内容**（一行，指向云盘直链）：

```
https://alist.decanas.top/d/Ani/2019-1/%E8%BC%9D%E5%A4%9C%E5%A7%AC...%5B01%5D%5B1080P%5D.mp4
```

`HEAD` 请求会返回 **302**（OpenList 重定向到真实直链），说明链接可用。

> **命名规则与 OpenList 官方 `drivers/strm` 驱动一致**：官方用
> `TrimSuffix(name, SourceExt(name)) + "strm"`，由于 `SourceExt` 会去掉点，
> `movie.mkv` → `movie.strm`（保留末尾的点，再拼 `strm`）。
> 本插件已用官方 Go 算法逐字节交叉验证（含 24 个特殊字符的 URL 编码）。
>
> **为什么是替换而不是追加**：追加风格下 `a.mkv` 和 `a.mkv.strm` 会**映射到同一个
> 本地文件**（都是 `a.mkv.strm`），互相覆盖；替换风格下前者得到 `a.strm`、
> 后者得到 `a.mkv.strm`，不会冲突（见 `test_video_and_strm_source_do_not_collide`）。
> 替换也是 CloudStrm 等同类插件的既有命名，便于平滑迁移。

> 为什么不用 `/api/fs/get` 返回的 `raw_url`？因为那可能是存储驱动的**临时签名直链**，
> 会过期。`/d/` 是每次播放都重新解析的稳定入口。

## 常见问题

**Q：提示「未授权（token 失效或未登录）」**
OpenList 的 token 默认 48 小时过期，且**服务端重启后所有 token 立即失效**（内存态）。
插件会自动重登一次；若仍失败，请检查 Token 是否被后台重置。

**Q：字幕没有下载下来**
1. 检查「启用文件下载」是否打开；
2. 检查该扩展名是否在「下载为本地文件的扩展名」列表里；
3. 检查文件是否被「跳过文件名」规则命中（内置规则会跳过含「广告/推广/公告」等字样的文件）；
4. 若设了「单次最多下载文件数」，可能是达到上限，下次任务会继续。

**Q：保存配置后会不会自动删除我的 strm？**
**不会。** 保存配置与定时任务都不包含任何删除动作。唯一的删除入口是插件**详情页**
的「清理失效项」和「清空全部 strm」按钮，且都需要你先看清单、再确认。旧版本配置里
若带有「自动删除」开关，升级后会被自动转换为安全模式并给出日志提示。

**Q：会不会误删我的 strm？**
不会。只有内容能被反解为 `/d/<path>` 的 strm 才会纳入清理候选，其它来源的 strm
一律跳过；且所有删除都要经过目录边界校验，越界直接拒绝。

**Q：某些正常文件被跳过了 / 需要跳过别的文件怎么办？**
内置过滤只针对明确的垃圾文件和系统残留。如果误伤，或用例特殊，可在配置页的
「③ 额外跳过的目录名」「④ 额外跳过的文件名」中自行调整（后者支持 `*` `?` 通配）。

**Q：能同时用多个 OpenList 吗？**
可以。每个任务行自带地址与凭据，互不影响。

**Q：缓存会不会导致漏掉新文件？**
不会。扫描根目录每次都重新拉取，子目录按 mtime 判断；OpenList 上目录内容变化时
mtime 会更新。若你的存储不维护 mtime，把「缓存最长有效时长」设为 `24` 强制每日刷新。

**Q：会不会把 OpenList 打爆？**
`refresh` 恒为 `false`，不会触发上游驱动刷新。启用缓存后常态下几乎不产生请求。

**Q：能和 CloudStrm 插件共存吗？**
可以，但请确保两者的输出目录不要重叠，否则会互相覆盖。
